# Pre-Commit Check Skill

介入ログから抽出した「コミット前に怠ると手戻り / PR レビュー混乱になる」項目を機械的にチェックする。/commit スキルを呼ぶ前段として使う。

## 使い方

```bash
cd /Users/yoshinotakuya/Documents/GitHub/sheetcraft

echo "=== 1. ステージ / 未ステージ差分 ==="
git status --short
echo ""
echo "=== 2. ステージ済み diff のサマリ ==="
git diff --cached --stat
echo ""
echo "=== 3. develop からの差分にノイズがないか ==="
git diff --stat origin/develop...HEAD
echo ""
echo "=== 4. 直近のコミット (粒度参考) ==="
git log --oneline -5
```

## コミット前に確認する項目

### A. 動作確認
- [ ] 変更を実機 / テスト / 型チェックのいずれかで確認したか
- [ ] 未検証ならコミットメッセージか直前のメッセージで「未検証」と明示する
- [ ] 「実装した」「直した」と言う前に必ず確認結果を提示（過去に Shift+クリック・Delete で 3 回手戻り）

### B. コミット粒度
- [ ] 変更内容を 1 行で要約できるか（できないなら粒度過大 → 分割）
- [ ] 独立した論点が 1 コミットに混ざっていないか（過去に `df31c5b` で 3 論点混在事例）
- [ ] Stop hook 発動を待たず、論点が完結したタイミングで自発的にコミット

### C. 差分ノイズ
- [ ] `git diff --stat origin/develop...HEAD` で意図しないファイルが混じっていないか
- [ ] `.claude/hooks/` 等の擬似削除 / 行末空白 / 改行差分が混入していないか
- [ ] `example/` のサンプルデータが意図せず変わっていないか（過去に character.json 破損事例）

### D. 検証チェックリスト提示
- [ ] 実装完了後、5-10 件の検証チェックリストを自発的にユーザーに提示
  - 例: 「以下を確認してください: 1) X が動く 2) Y が壊れていない ...」
- [ ] ユーザーから「確認項目を示して」と要求される前に出す

## 省略可な場合

- ドキュメントのタイポ修正 / コメント修正のみ
- 動作に影響しないリファクタリング（変数名変更等）でテストが緑

省略する場合は「pre-commit-check 省略：理由」を 1 行で出す。
